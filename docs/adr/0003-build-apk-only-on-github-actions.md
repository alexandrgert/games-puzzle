# Контекст

Первоначальный критерий предполагал локальный прогон Gradle и получение APK. Во время проверки локальная sandbox-среда прерывала Gradle daemon networking, а прямой JVM-запуск завершался на Kotlin-компиляции без результата; затем пользователь уточнил требование: APK должен собираться только на GitHub.

# Решение

Debug APK собирается только в GitHub Actions: workflow выполняет `./gradlew test assembleDebug` и публикует APK как artifact. Локальная APK-сборка не является критерием приёмки; подписанный release остаётся отдельным условным процессом с существующими секретами.

# Почему

Рассматривалось сохранение обязательной локальной APK-сборки с дальнейшими обходами ограничений sandbox, но это противоречит уточнённому GitHub-only требованию и привязывает приёмку к нестабильным свойствам локальной среды. Рассматривалась также публикация полноценного GitHub Release, но выпуск является отдельным внешним действием, тогда как текущая работа требует проверяемый debug artifact. GitHub Actions даёт единый воспроизводимый путь сборки без release-секретов.

# Последствия

Подтверждение успешной APK-сборки зависит от выполнения GitHub Actions и доступности опубликованного artifact. Локальная среда может использоваться для иных проверок, но локально полученный APK не считается результатом выпуска. Изменения workflow становятся частью критического пути поставки, а публикация и подпись release не происходят автоматически.
