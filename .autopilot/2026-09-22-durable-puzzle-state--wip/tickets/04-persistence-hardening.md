# 04 — Довести постоянное сохранение до безопасного рабочего режима

**Требования:** R01, R02, R03
**Blocked by:** 01
**Зона:** `app/src/main/java/.../data/`, `app/src/main/java/.../ui/play/`, соответствующие тесты
**Волна:** 3
**Status:** ready

## Что должно заработать

Периодический UI tick не создаёт очередь записей на диск, JSON-кодирование выполняется вне main thread, а тесты доказывают порядок конкурентных сохранений и публичный контракт store вместо внутренних helper-функций.

## Из брифа, дословно

> «делай реализацию»
> «устойчивое сохранение партии, lifecycle/process-death тесты»

## Разделы спецификации

Решения по реализации и границы `ActivePlaySessionStore`/`PlayViewModel`.

## Критерии приёмки

- [ ] `tick()` обновляет UI-время без durable write; игровые изменения и `ON_STOP` сохраняются
- [ ] JSON encode/decode выполняются на IO dispatcher, не на main thread
- [ ] Тест порядка принудительно задерживает раннюю запись и доказывает, что поздняя не может обогнать её
- [ ] Store-тесты проходят через публичные `save/load/clear` и проверяют очистку повреждённой записи
- [ ] Lifecycle-тест предыдущего таска остаётся неизменным и зелёным в GitHub CI
